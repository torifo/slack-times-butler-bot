# Slack App インストール拒否の原因候補

Slack App の `Install to Workspace` 実行時に
`このワークスペースにはこのアプリをインストールすることはできません`
と表示された場合の、原因候補を可能性順に整理する。

## 1. 可能性が高い原因

### 1.1 ワークスペースのアプリインストール権限が制限されている

もっとも可能性が高い。

よくある状態:

* アプリ追加を管理者またはオーナーだけに制限している
* メンバーは申請だけ可能で、承認が必要
* 外部アプリ導入をワークスペースポリシーで止めている

確認ポイント:

* Slack 管理画面で、アプリ追加権限が誰にあるか
* 申請フローが必要な設定になっていないか
* すでに管理者承認待ち状態になっていないか

対処:

* 管理者またはオーナーにインストールしてもらう
* 申請内容に必要 scope と用途を添えて承認してもらう

### 1.2 選択したワークスペースが違う

Slack App 作成時に選んだ workspace と、実際に入れたい workspace がずれているケース。

確認ポイント:

* Slack App 作成時の `Pick a workspace`
* ブラウザで開いている Slack の workspace
* 管理画面の右上や URL に表示されている workspace 名

対処:

* 対象 workspace で App を作り直す
* 既存 App が別 workspace 用なら混同しない

### 1.3 Slack Enterprise / 組織ポリシーでブロックされている

Enterprise Grid や組織ポリシー下では、workspace 単体ではなく組織管理側で制限されることがある。

確認ポイント:

* 組織レベルで App 管理が一元化されていないか
* 許可リスト方式になっていないか
* カスタム App の利用自体が制限されていないか

対処:

* 組織管理者に、対象 App の許可可否を確認する
* 必要なら allowlist 追加を依頼する

## 2. 中程度の可能性がある原因

### 2.1 要求 scope が厳しすぎて承認対象になっている

今回の仕様では scope が広めで、`assistant:write`、`files:write`、`canvases:write`、`bookmarks:write`、`lists:write`、`reminders:write` などが含まれている。
権限の強さによっては、その場での自己インストールが拒否され、管理者承認が必須になる。

確認ポイント:

* どの scope を追加した直後に申請が必要になったか
* core 機能に不要な scope まで最初から載せていないか

対処:

* 最初は MVP に必要な scope のみに絞る
* 最低限の例:
  * `app_mentions:read`
  * `channels:history`
  * `chat:write`
  * `commands`
  * `links:read`
  * `reactions:write`
* 追加 scope は動作確認後に段階的に申請する

### 2.2 社内の承認フローで申請中になっている

エラー表示というより「この場で完了できない」状態で、実際には申請キューに載っている可能性がある。

確認ポイント:

* Slack 側に申請済み通知が出ていないか
* 管理者に承認待ちの通知が飛んでいないか

対処:

* 承認待ちステータスを確認する
* 承認側に用途と必要 scope を説明する

## 3. 低めだが確認しておくべき原因

### 3.1 App 設定の不整合

App 自体は作成できていても、設定途中の状態が影響する場合がある。

確認ポイント:

* OAuth & Permissions に最低限の Bot Token Scope が入っているか
* App の配布対象 workspace が想定どおりか
* Basic Information 上で App が正常に作成されているか

対処:

* 不要な設定を減らして再作成する
* 最小構成で App を作ってから scope を足す

### 3.2 ブラウザセッションや権限キャッシュの問題

低確率だが、Slack 管理画面のログイン先やセッションのズレで権限判定が崩れることがある。

確認ポイント:

* ブラウザで複数 workspace に同時ログインしていないか
* シークレットウィンドウだと挙動が変わるか

対処:

* 管理画面を開き直す
* 正しい workspace で再ログインする

## 4. 今回の状況でまず疑う順番

1. ワークスペース側でアプリ追加が管理者承認制になっている
2. 広い scope を要求していて、その場での自己インストールが許可されていない
3. App を作成した workspace と入れたい workspace がずれている
4. 組織ポリシーまたは Enterprise 側でカスタム App が制限されている

## 5. 次に確認するとよい項目

* 管理者へ「承認待ち」になっているか確認する
* 現在要求している Bot Token Scope 一覧を見直す
* MVP に不要な scope を一度外せるか検討する
* App を作成した workspace が正しいか再確認する

## 6. 補足

今回の `times-Butler` は MVP 時点では以下の scope があれば主要動線の検証を始めやすい。

* `app_mentions:read`
* `channels:history`
* `chat:write`
* `commands`
* `links:read`
* `reactions:write`

最初から将来用の広い scope を全部積むより、まず最小権限でインストール可否を通すほうが切り分けしやすい。
